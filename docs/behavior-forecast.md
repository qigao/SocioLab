# Past-only behavior forecasts and separate target scoring

For receipt-versioned event inputs, the [journal adapter](journal-forecast.md)
constructs this profile's history and target artifacts at explicit cutoffs,
preserving the evidence for previously issued versions.

This profile compares three fixed **point forecasts** of the next observed
behavior code: persistence, own-lag ordinary least squares (OLS), and own-lag
OLS with one outgoing-neighbor feature. Predictions are created from a
historical panel and saved before a separate command accepts target behavior.
The forecast command has no future-network or target-behavior input.

The implementation uses original `numpy.linalg.lstsq` and NetworkX neighbor
enumeration. It is separate from the retrospective [joint SAOM](coevolution.md)
and introduces no new estimator dependency. A completed forecast or a lower
error on one historical split does not establish causal influence, deployment
accuracy, or validity for an unrelated behavioral outcome.

## Run the complete synthetic example

The three checked-in files contain four invented people and invented category
codes. Their purpose is to demonstrate the two command boundaries; they are
not generated by a fitted social mechanism and do not validate a model.

```bash
python -m sociolab forecast create examples/forecast/synthetic.history.json examples/forecast/synthetic.spec.json > /path/to/private-prediction.json
python -m sociolab forecast score /path/to/private-prediction.json examples/forecast/synthetic.target.json > /path/to/aggregate-score.json
```

`create` emits a forecast artifact containing **actor identifiers and per-actor
predictions**. Keep that artifact with the private input data. `score` emits
aggregate errors, comparison denominators, and hashes; it does not export the
actor list, individual errors, or target measurements. All commands emit strict
JSON to stdout. Invalid input fails rather than dropping people or filling
unknown behavior.

## Input boundaries and time

The historical input uses `sociolab.longitudinal.v1` and contains **only known
waves**. It requires a fixed actor roster, complete declared network
observations, and an observed behavior value for every actor in every supplied
wave. This bounded profile allows at most 200 actors and 32 waves. Consecutive
wave indices must have one common positive gap; the target index must be
exactly one such gap beyond the last historical wave.

Wave indices define the prediction period. They do not by themselves prove a
calendar-time horizon or that an observation was actually available at that
time. The panel format has no receipt history. For an eventual live workflow,
construct the historical panel from a fixed journal `knowledge_cutoff` under an
explicit measurement policy before calling this predictor. Later-received
corrections must not be inserted into an already issued forecast's input.

The specification has exactly this shape:

```json
{
  "schema": "sociolab.behavior-forecast.v1",
  "profile": "own-lag-outgoing-gap-ols-v1",
  "behavior": {
    "variable": "invented_behavior_level_1_to_5",
    "minimum": 1,
    "maximum": 5,
    "measurement_reference": "synthetic:invented-category-codes"
  },
  "target_time_index": 2,
  "research_question": "Does origin-wave network information improve next-wave prediction on this declared task?"
}
```

The behavior variable must match the panel. Bounds are declared independently
of the future observations; the profile permits 2–100 integer levels starting
at a nonnegative minimum. It does not infer bounds from the target or require
the endpoints to occur in the training sample. Missing, fractional or
out-of-scale measurements are rejected. These codes are not automatically
equal-interval measurements of a physical quantity.

## Three fixed forecasts

For actor `i` at an observed origin wave `t`, let `y(i,t)` be that actor's known
behavior. Let `N+(i,t)` be the graph's outgoing neighbors, obtained through
original `networkx.DiGraph.successors`.

The network feature is `mean(y(j,t) for j in N+(i,t)) - y(i,t)`. With no outgoing
neighbors the feature is explicitly zero. This convention does not invent
neighbor behavior or remove the actor.

| Forecast | Formula | Training columns |
| --- | --- | --- |
| Persistence | `y(i,t)` | No fitted parameters |
| Own lag | `beta0 + beta1*y(i,t)` | Intercept, own lag |
| Own lag and network | `gamma0 + gamma1*y(i,t) + gamma2*neighbor_gap(i,t)` | Intercept, own lag, outgoing-neighbor gap |

Both OLS fits use the same actor rows from every adjacent transition within the
historical prefix. All features for a training transition come from its
**origin wave**; its later known behavior supplies the label. Forecast features
come from the last historical wave only. There is no trend feature, sample
selection, standardization, hyperparameter search, or use of all-wave SAOM
parameters.

The solver is `numpy.linalg.lstsq(X, y, rcond=None)`. An OLS fit requires more
training rows than columns and full column rank. Otherwise that model returns
`NOT_ESTIMABLE` with its reason; the persistence forecast remains available.
The report retains rank, singular values and condition number. It does not
silently accept a rank-deficient minimum-norm solution as an identified model,
change features, or try another estimator. NumPy documents the solver's rank
and minimum-norm behavior in its [official reference](https://numpy.org/doc/stable/reference/generated/numpy.linalg.lstsq.html).

Raw continuous predictions and predictions clipped to the **declared** scale
are both retained. Predictions are not rounded to categories. These outputs
are point predictions, not probabilities; calibration and prediction intervals
are not estimated.

## Saved artifacts and scoring

The forecast artifact uses `sociolab.behavior-forecast-artifact.v1`. It binds the
historical panel hash, historical times and revisions, specification hash,
training-feature and label hashes, forecast-feature hashes, solver diagnostics,
runtime versions and predictions. It does not bind a full source archive or a
future target. The canonical `content_hash` detects accidental content changes;
it is not authentication, an external timestamp or proof of a blind experiment.

The separate target uses `sociolab.behavior-target.v1` with exactly these fields:
`schema`, `dataset_id`, `origin`, `source_reference`, `behavior_variable`,
`time_index`, `source_revision`, and an actor-keyed `behavior` object. It contains
no future network. Scoring requires the same dataset, source, behavior variable,
target time and complete fixed roster as the prediction artifact. Missing
outcomes fail scoring; no per-model subset or silent intersection is selected.

The primary case metric is clipped **mean absolute error (MAE)**. Clipped
**root mean squared error (RMSE)** is secondary; raw metrics and clipping counts
are also reported. Both metrics measure a declared loss on category codes,
not actual consumption amounts. Network-minus-own and network-minus-persistence
differences use the same evaluation set. Negative differences favor the
network model. No coefficient significance, IID actor bootstrap, confidence
interval, or causal conclusion is inferred from these dependent observations.

`score` validates and evaluates the saved artifact. It does not fit again,
change coefficients or rewrite predictions. A historical holdout is distinct
from fitting all available waves: only observations before each forecast
origin may train its model. See [Hyndman and Athanasopoulos, time-series
cross-validation](https://otexts.com/fpp3/toolbox.html#time-series-cross-validation).

## The s50 numerical teaching case

The [official source](https://www.stats.ox.ac.uk/~snijders/siena/s50_data.htm)
provides three friendship waves and three self-reported alcohol-frequency
categories for a 50-person excerpt. It explicitly restricts the excerpt to
numerical illustration because it is **not a properly delineated network**.
The categories 1–5 range from no consumption to more than once per week; their
numeric spacing is not a physical amount or a validated interval scale.

This case uses source waves 1/2 to predict wave 3 (indices **0/1 → 2**): train
on `0 → 1`, issue at `1`, and score against `2`. The future network is never
used. All 50 early-roster actors remain in the prediction and scoring set.
Only one transition is held out; there is no multiple-origin rolling result.

```bash
python -m sociolab forecast s50-history /path/to/s50_data.zip > /path/to/private-history.json
python -m sociolab forecast create /path/to/private-history.json examples/forecast/s50.spec.json > /path/to/private-prediction.json
python -m sociolab forecast s50-target /path/to/s50_data.zip > /path/to/private-target.json
python -m sociolab forecast score /path/to/private-prediction.json /path/to/private-target.json > /path/to/aggregate-score.json
```

The new history reader consumes only the first two networks and first two
behavior columns. It accepts absent or invalid unused future values, within
the source-format safety bounds. The shared behavior member has to be
decompressed, but unused tokens are neither parsed as observations nor hashed
into the history. The prediction subprocess receives only the resulting
history file and specification. The third behavior column is extracted in a
later step; the third network is not required by either step.

This is **retrospective, single-transition numerical holdout evaluation**.
The same three-wave dataset was already used in earlier retrospective model
work. Fixing this run's protocol before computing its errors does not make the
dataset previously unseen, the experiment prospective, or the protocol publicly
preregistered. Historical receipt availability and population generalization
remain unverified. The case does not validate participation, cooperation,
language, conflict prediction, or a real-time service.

The checked-in [protocol](experiments/2026-11-28-behavior-forecast/protocol.json)
fixes the split, features, models and scoring before this run's predictions.
The [runner](experiments/2026-11-28-behavior-forecast/run_forecast_case.py) saves
private predictions before extracting the target and records each actual CLI
step. It requires fresh output paths and keeps actor-level files outside the
checkout:

```bash
python docs/experiments/2026-11-28-behavior-forecast/run_forecast_case.py /path/to/s50_data.zip --private-directory /path/to/private-forecast --output /path/to/aggregate-evidence
```

### Recorded result: 2026-11-28

The fixed run completed on all 50 actors. Both OLS designs were full rank.
No model needed clipping, so the raw and clipped errors are equal in this run.
Lower values are better; the units are **behavior category-code distance**.

| Forecast | Actors | Clipped MAE (primary) | Clipped RMSE | Predictions clipped |
| --- | ---: | ---: | ---: | ---: |
| Persistence | 50 | 0.660000000 | 0.948683298 | 0 |
| Own lag | 50 | 0.640718016 | 0.795452369 | 0 |
| Own lag and network | 50 | 0.640102373 | 0.793576165 | 0 |

The network model's MAE was 0.000615643 lower than own-lag OLS, about **0.10%**
of the own-lag error. Its MAE was 0.019897627 lower than persistence. Most of
the improvement over persistence was already present in the own-lag model;
the extra network feature made only a small difference on this particular
held-out transition. This result does not demonstrate a stable predictive
advantage, statistical significance, or causal peer influence. No model,
feature, split or scoring rule was changed after seeing these errors.

This initial profile uses the known network and behavior **at the forecast
origin**. It does not estimate the effect of adding or removing a particular
tie, explain a speech or conflict event, or predict the future graph. Such
questions require their own measured outcomes and evaluation designs.

## Python API

```python
from sociolab.panels import load_panel
from sociolab.behavior_forecast import (
    load_behavior_forecast_spec, make_behavior_forecast,
    load_behavior_forecast, load_behavior_target, score_behavior_forecast,
)

forecast = make_behavior_forecast(
    load_panel("history.json"), load_behavior_forecast_spec("specification.json")
)
# Save forecast before separately obtaining target observations.
score = score_behavior_forecast(
    load_behavior_forecast("saved-prediction.json"),
    load_behavior_target("target.json"),
)
```

The source helpers `load_s50_forecast_history(path)` and
`load_s50_forecast_target(path)` live in `sociolab.s50_forecast`. The former also
returns aggregate provenance of only the consumed prefix values. Source format
checks and matching hashes do not independently verify participant reports.

For multiple origins, use the separate [planned temporal evaluation](forecast-evaluation.md).
It fixes a schedule from the initial history, verifies complete expanding
prefixes, and recomputes every saved forecast's score without refitting. Its
invented multi-origin execution does not add a second real holdout to s50.
